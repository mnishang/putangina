# Sable & Stem Coffee

A responsive editorial storefront for Sable & Stem Coffee. The site includes the supplied animated text ribbon, staggered navigation, an original lenticular best-seller carousel, a categorized full menu, Philippine-peso pricing, an interactive cart, pickup-order submission, an itemized receipt, and a protected sales overview.

## Start in Manus Cloud

After syncing the project into the Cloud Webdev workspace, run:

```sh
npm install
npm run dev:cloud
```

The Cloud command listens on `0.0.0.0:5173`, matching the project's session preview port. In the Cloud runtime, the managed MySQL connection is provided through the process environment. Check `/api/health` for `{"ok":true}` before trying checkout. Do not place database credentials in source files, `.env` files, or chat.

## Start locally

```sh
npm install
npm run dev
```

The local Desktop command listens only on `127.0.0.1:5173`. It requires the managed database connection to be present in the local process environment; a plain PowerShell process without that connection cannot save orders. Do not copy the shared managed database URL into a local file or paste it into chat.

### Connect your own MySQL database (local development)

The storefront works out of the box by saving orders and inventory to the browser, but you can connect a real database:

1. **Install MySQL Server 8 Community** (or MariaDB) from `dev.mysql.com/downloads/installer`. Choose *Server only* (add *Workbench* for a GUI). Set a root password and keep port `3306`.
2. **Create the database** once, in Workbench or the MySQL command line:
   ```sql
   CREATE DATABASE sable_stem CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```
3. **Create your `.env`** by copying the template and editing it:
   ```sh
   Copy-Item .env.example .env
   ```
   Set `DATABASE_URL`, and give `ADMIN_API_TOKEN` and `VITE_ADMIN_API_TOKEN` the same long random string.
4. **Start with the API server** (this serves the site *and* the database API):
   ```sh
   npm run dev:local
   ```
   On first start the server creates the `ss_orders`, `ss_order_items`, and `ss_inventory` tables automatically.

When the database is connected, the Inventory page shows **"Saved to database"**. If it still says **"Saved in this browser"**, the page explains why (database not reachable, or a mismatched admin token).

The `.env` file is ignored by git. `ADMIN_API_TOKEN` is a development convenience that replaces the Manus OAuth sign-in; never enable it on a public deployment.


## Order behavior

Customers can browse the additional drink categories, add products, adjust quantities, remove lines, and see Philippine-peso totals. Checkout submits a pickup request and stores the customer's name, contact number, optional note, order total, and immutable item/price snapshots. The storefront does **not** collect online payment or claim that an order has been paid. The order number shown after successful submission is generated by the server.

After the server confirms the database commit, an itemized popup receipt shows the order reference, drink quantities and prices, pickup status, and PHP total.

The menu uses editable illustrative PHP price points because no owner-approved price list or live currency-conversion rate was supplied. Replace those values in `src/menu-data.js` before treating them as final café prices.

The first server start applies additive, idempotent `ss_`-prefixed order-table migrations; it does not seed sample orders. The project-managed MySQL database is shared with the published runtime. Do not insert demo orders into that shared database.

## Admin and sales analysis

Open `/admin` and sign in with the authorized Manus account. The project setting `ADMIN_EMAIL` must be provided as a protected environment value before access is granted. The dashboard reads real orders only and reports order count, submitted order value, average order value, daily order value, popular drinks, and recent order details. An empty database is shown as an empty state; no sales are fabricated. Order value is not payment settlement.

## Structure

- `src/CommerceApp.jsx` — storefront, cart state, checkout request, and `/admin` routing.
- `src/menu-data.js` — shared source of truth for product IDs, descriptions, categories, and PHP prices.
- `src/components/FullMenu.jsx`, `CartDrawer.jsx`, `AdminSalesPage.jsx`, `AdminInventoryPanel.jsx`, `OrderReceiptDialog.jsx` — menu, cart/checkout, protected dashboard, inventory management, and receipt UI.
- `src/components/` — `TextLoop`, `StaggeredMenu`, `PeekRating`, and original `LenticularCarousel` components.
- `src/index.css` — the single stylesheet for the whole site (storefront and admin).
- `src/local-orders.js` — saves orders to the database when available and to the browser otherwise.
- `src/inventory.js` — inventory items, stock-status rules, and form validation.
- `server.mjs` — same-origin order + inventory API, MySQL migrations, Manus OAuth (or local-token) admin gate, and dashboard queries.
- `public/manus-routes.json` — storefront and admin route metadata.

`npm run build` creates the Vite client bundle. `npm run lint` runs the existing ESLint checks. `npm install` refreshes the dependency lock when the declared package set changes.
